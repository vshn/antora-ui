= Brands

One repository builds four UIs.
The shared UI lives in `src/` and carries no brand string.
Each brand is a directory under `brands/` that fills the slots the shared templates leave open.
The brands are `vshn`, `appuio`, `k8up` and `syn`, listed in `brands.json`.

== What a brand owns

[cols="1,3"]
|===
| `css/tokens.css` | the palette, and the color slots the shared stylesheets read
| `css/brand.css` | the logo rule and any rule only this brand needs
| `img/` | the logo and the favicons
| `partials/brand-logo.hbs` | the element in the navbar
| `partials/brand-links.hbs` | the navbar dropdowns
| `partials/brand-footer.hbs` | the footer text
| `partials/brand-icons.hbs` | the favicon and apple-touch-icon links
| `partials/brand-meta.hbs` | `twitter:site` and any other brand meta tag
|===

A brand does not own the markup around its slots.
The navbar, the search box and the admonition rendering are shared, so they cannot drift per brand.
A brand that needs a structural change changes the shared file, where every brand gets it.

== Building one

[source,console]
----
$ npx gulp bundle --brand=appuio     # build/ui-bundle-appuio.zip
$ npx gulp preview --brand=k8up      # http://localhost:5252
----

The build stages `src/` into `build/staging`, copies the brand over it, then compiles, fingerprints and packs the result.
The brand comes from `--brand=<name>`, then from the `BRAND` environment variable, then defaults to `vshn`.
An unknown name fails the build rather than producing a VSHN-colored bundle under another brand's name.

The VSHN bundle is called `ui-bundle.zip` and not `ui-bundle-vshn.zip`, because handbook, kb, products and appcat pin that name.
Every other brand is called `ui-bundle-<brand>.zip`.
`brands.json` records the file name for every brand.

== Adding one

. Create `brands/<name>/` with `css/tokens.css`, `css/brand.css`, an `img/` directory and the five partials listed above.
The practical way to start `tokens.css` is to copy an existing brand's file and change the values, because this page does not list the color slot names and copying is the only way to get the complete set.
Rename the variables that start with the old brand's prefix, such as `--k8up-blue`, to start with `--<name>-`: `test/brand-free.spec.js` treats every other variable as a slot that all brands must declare.
. Add one object to `brands.json` with the keys `name`, `title`, `bundle`, `logo` and `navbarBackground`.
`navbarBackground` is the color the tests expect `.navbar` to compute to, for example `"rgb(246, 247, 249)"`.
. Build the bundle first with `npx gulp bundle --brand=<name>`, then run `BRAND=<name> npx playwright test` and `BRAND=<name> npm run test:bundle`.
The bundle tests fail rather than skip when the zip is missing, hence the order.
`npm run test:bundle` is the only command that runs `test/brand-css.spec.js`.

The CI matrix reads `brands.json` with `jq`, so there is no workflow to edit.
The workflow validates brand names before they reach a shell.

== Advertising a site as a search engine

A site can offer its search to the browser's address bar through OpenSearch.
The UI generates the descriptor, so no site hardcodes its domain.
A site needs two things.

. In the playbook, under `site.keys`, set `opensearch: true` and `searchPagePath`, the path of the search page relative to the site root, for example `user/search.html`.
The UI adds the discovery link to every page only when `site.url`, `opensearch` and `searchPagePath` are all set, so a misconfigured site advertises nothing.
. Add a page with these two lines:
+
[source,asciidoc]
----
= OpenSearch
:page-layout: opensearch
----

Antora renders that page through `src/layouts/opensearch.hbs`, which writes an OpenSearch descriptor instead of HTML.
The descriptor is built from the site's own `site.url`, `site.title` and `searchPagePath`.
It cannot be a static file in the UI, because Antora copies static files verbatim and OpenSearch needs absolute URLs.
The nginx image serves the generated page at `/opensearchdescription.xml` with the content type `application/opensearchdescription+xml`.

The OpenSearch specification limits `ShortName` to 16 characters, and the layout does not truncate it, because a name that is wrong is better noticed than hidden.
It falls back to `site.title`, which in practice is always too long: the real titles of these sites run from 31 characters ("APPUiO Cloud User Documentation") to 45 ("K8up Kubernetes Backup Operator Documentation").
So set `opensearchShortName` under `site.keys` as a matter of course, for example `K8up Docs`.
`Description` always uses `site.title`, which has no such limit.

== Looking at a brand

The tests check computed colors, which does not tell you whether a page looks right.
To see a brand, capture its screenshots:

[source,console]
----
$ SCREENSHOTS=1 BRAND=k8up npx playwright test test/screenshot.spec.js
$ sh test/screenshots.sh
----

The first command captures one brand.
The second reads `brands.json` and captures every brand, one after the other, because two builds in the same workspace delete each other's files.
Both write to `screenshots/<brand>/`, which git ignores: `style-guide.png` (the full style-guide page), `404.png`, `navbar-hover.png` (the navbar with the first dropdown open) and `search.png` (a search with results).
The spec skips itself unless `SCREENSHOTS=1` is set, so `npm test` does not write images.

CI runs the same spec for each brand and attaches the images to the run as the `screenshots-<brand>` artifact.
A reviewer can see a brand from the run page without building it.

== The tests that keep this working

`test/brand-free.spec.js` fails if anything under `src/` names a brand, in its contents or in its file name.
It also asserts that all four brands declare the same set of color slots, and that this set matches what `src/` reads but never declares.
That test is the whole consolidation: it fails the day someone adds a VSHN link to a shared partial, which is how the four forks came about.

`test/brand.spec.js` checks, for the selected brand, that the logo is served, that the navbar's computed color matches `navbarBackground` in `brands.json`, that every referenced favicon exists, and that every declared `sizes="NxN"` matches the PNG's real pixel dimensions.

`test/bundle.spec.js` guards the packaged zip.
Among other checks, it fails if one brand's images appear in another brand's zip.
It also checks that no entry is compressed to 64 KiB or more, that already compressed formats are stored rather than compressed again, that fonts and images are valid binaries, that the CSS and JS are fingerprinted and every asset a template references is shipped, and that the Font Awesome font is copied byte for byte.
